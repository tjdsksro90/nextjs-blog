MDX의 가장 큰 장점은 **글 안에 React 컴포넌트를 넣을 수 있다**는 것이다. 이번에는 블로그 글에 자주 쓸 컴포넌트 두 개를 만들었다.

- **Callout**: "주의", "팁" 같은 강조 박스
- **Counter**: 글 안에서 직접 눌러 보는 예제

## 1. 글에서 import 없이 쓰기

컴포넌트를 글에서 쓰려면 원래 글 맨 위에서 import해야 한다. 글마다 import를 적는 건 번거롭다. 그래서 MDX에 **기본 컴포넌트 목록**을 등록했다.

```tsx title="src/mdx-components.tsx"
const components: MDXComponents = {
  // 소문자 키: 마크다운이 만드는 HTML 태그를 바꿔치기
  pre: CodeBlock,

  // 대문자 키: 글에서 <Callout>, <Counter>로 바로 사용
  Callout,
  Counter,
};

export function useMDXComponents(): MDXComponents {
  return components;
}
```

fumadocs 설정(`source.config.ts`)의 `providerImportSource: '@/mdx-components'`가 이 파일을 모든 글에 연결해 준다.

- **소문자 키**(`pre`, `a`, `img` 등)는 마크다운이 만드는 기본 태그를 내 컴포넌트로 바꾼다. 코드 블록에 파일 이름을 붙인 것이 이 방식이다.
- **대문자 키**는 글에서 JSX 태그처럼 쓸 수 있는 새 컴포넌트가 된다.

## 2. Callout: 서버 컴포넌트

```tsx title="src/components/Callout.tsx"
const variants = {
  note: { label: 'Note', className: 'border-sky-500/50 bg-sky-500/5 ...' },
  warn: { label: 'Warning', className: 'border-amber-500/60 bg-amber-500/5 ...' },
  tip: { label: 'Tip', className: 'border-emerald-500/50 bg-emerald-500/5 ...' },
} as const;

export function Callout({ type = 'note', title, children }: CalloutProps) {
  const variant = variants[type];
  return (
    <aside className={`not-prose my-6 rounded-r-lg border-l-4 px-4 py-3 ${variant.className}`}>
      <strong className="mb-1 block text-sm font-semibold">{title ?? variant.label}</strong>
      <div className="[&>p+p]:mt-2">{children}</div>
    </aside>
  );
}
```

글에서는 이렇게 쓴다.

```mdx
<Callout type="warn" title="주의">
  이 API는 Next 16부터 바뀌었다.
</Callout>
```

<Callout type="warn" title="주의">
  이 API는 Next 16부터 바뀌었다.
</Callout>

- 종류(`type`)마다 색과 기본 제목을 객체 하나에 모아 두었다. 종류를 추가하려면 한 줄만 늘리면 된다.
- `keyof typeof variants`로 타입을 만들면 `type="danger"`처럼 없는 종류를 쓸 때 타입 에러가 난다.
- 배경은 `bg-sky-500/5`처럼 아주 옅은 반투명이라 라이트와 다크 모드 모두 어울린다.
- 보여 주기만 하고 상호작용이 없으니 **서버 컴포넌트**다. 브라우저로 JS가 가지 않는다.

## 3. not-prose: 본문 스타일 끊기

글 본문은 `@tailwindcss/typography`의 `prose` 클래스 안에 있다. prose는 안쪽의 `<p>`, `<strong>`에 여백과 글자 크기를 입힌다. 그대로 두면 박스 안 문단에도 위아래 여백이 크게 생겨 박스가 뚱뚱해진다.

`not-prose` 클래스를 붙이면 **그 안쪽에는 prose 스타일이 적용되지 않는다.** 그 대신 박스 안 여백과 글자 크기를 직접 정했다.

```tsx
<div className="[&>p+p]:mt-2">{children}</div>
```

MDX는 박스 안에 쓴 글을 `<p>`로 감싸서 넘겨준다. `[&>p+p]:mt-2`는 "문단 바로 다음 문단"에만 위 여백을 줘서, 문단이 여러 개일 때만 살짝 띄운다.

## 4. Counter: 클라이언트 컴포넌트

```tsx title="src/components/Counter.tsx"
'use client';

import { useState } from 'react';

export function Counter({ initial = 0 }: { initial?: number }) {
  const [count, setCount] = useState(initial);
  return (
    <div className="not-prose my-6 flex items-center gap-4 rounded-lg border border-line p-4">
      <button onClick={() => setCount((c) => c + 1)}>+1</button>
      <button onClick={() => setCount(initial)}>초기화</button>
      <span>count = {count}</span>
    </div>
  );
}
```

직접 눌러 보자.

<Counter />

클릭과 상태(`useState`)가 필요하니 `'use client'`를 붙였다.

### 서버 글 안에 클라이언트 컴포넌트

글 페이지 전체는 서버 컴포넌트다. 그 안에 클라이언트 컴포넌트를 섞어 넣으면 어떻게 될까?

- 글 본문은 서버에서 HTML로 만들어진다. 브라우저로 JS가 가지 않는다.
- Counter 부분만 JS가 브라우저로 가서 클릭에 반응한다.

글 전체를 클라이언트로 만들 필요 없이, **상호작용이 필요한 부분만** 클라이언트가 된다.

## 마무리

- `mdx-components.tsx`에 대문자 키로 등록하면 글에서 import 없이 컴포넌트를 쓴다.
- 보여 주기만 하는 컴포넌트(Callout)는 서버, 상호작용이 있는 컴포넌트(Counter)는 클라이언트로 만든다.
- 서버 글 안에 클라이언트 컴포넌트를 섞으면 그 부분의 JS만 브라우저로 간다.
- 본문 안 컴포넌트에는 `not-prose`를 붙이고 스타일을 직접 정한다.
