글이 몇 개 없을 때는 티가 안 나지만, 쌓이기 시작하면 필요한 기능들이 있다. 세 가지를 붙였다.

| 기능         | 위치       | 모습                       |
| ------------ | ---------- | -------------------------- |
| 연도별 묶기  | 홈 글 목록 | **2026** 아래에 그 해 글들 |
| 이전/다음 글 | 글 맨 아래 | ← 이전 글 / 다음 글 →      |
| 읽는 시간    | 글 날짜 옆 | 2026년 11월 7일 · 3분      |

재미있는 건 세 기능 모두 **이미 최신순으로 정렬된 `getPosts()` 배열**만 있으면 된다는 점이다.

## 1. 연도별 묶기

`[글, 글, 글, ...]`을 `[{ year: '2026', posts: [...] }, { year: '2025', posts: [...] }]` 모양으로 바꾼다.

```ts title="src/lib/posts.ts"
export function groupByYear(posts: Post[]) {
  const groups: { year: string; posts: Post[] }[] = [];
  for (const post of posts) {
    const year = post.date.slice(0, 4); // '2026-11-05' → '2026'
    const last = groups.at(-1);
    if (last?.year === year) last.posts.push(post);
    else groups.push({ year, posts: [post] });
  }
  return groups;
}
```

이미 최신순이라 **같은 해 글은 붙어 있다.** 그래서 처음부터 끝까지 한 번만 돌면서, 마지막 묶음과 같은 해면 거기에 넣고 다르면 새 묶음을 만들면 된다. `Map`이나 `Object.groupBy`를 써도 되지만, 순서가 이미 맞아 있으니 이 방법이 가장 단순하다.

홈에서는 묶음마다 연도 제목을 달고 기존 `PostList`를 그대로 썼다.

```tsx title="src/app/page.tsx"
{
  groupByYear(getPosts()).map(({ year, posts }) => (
    <section key={year}>
      <h2>
        {year} <span>{posts.length}편</span>
      </h2>
      <PostList posts={posts} />
    </section>
  ));
}
```

## 2. 이전/다음 글

지금 글이 배열에서 **몇 번째인지**만 알면 된다.

```ts title="src/lib/posts.ts"
export function getAdjacentPosts(slug: string) {
  const posts = getPosts();
  const i = posts.findIndex((post) => post.slug === slug);
  if (i === -1) return { prev: undefined, next: undefined };
  return { prev: posts[i + 1], next: posts[i - 1] };
}
```

헷갈리는 건 방향이다. 배열은 **최신순**이니 인덱스가 클수록 오래된 글이다.

- 이전 글(더 오래된 글) = `i + 1`
- 다음 글(더 최신 글) = `i - 1`

가장 최신 글에서는 `posts[-1]`, 가장 오래된 글에서는 `posts[length]`가 되는데, 둘 다 `undefined`라서 따로 검사하지 않아도 된다.

```tsx title="src/components/PostNav.tsx"
<nav className="grid sm:grid-cols-2">
  {prev ? <NavCard post={prev} label="← 이전 글" /> : <div />}
  {next ? <NavCard post={next} label="다음 글 →" align="right" /> : <div />}
</nav>
```

한쪽 글이 없을 때 빈 `<div />`를 두는 게 포인트다. 이게 없으면 "다음 글" 카드가 왼쪽 칸으로 밀려와서 방향이 헷갈린다.

## 3. 읽는 시간

"글자 수 ÷ 1분에 읽는 글자 수"로 계산한다. 한국어는 1분에 약 500자로 잡았다. 고민한 것은 두 가지였다.

- **언제 셀까?** 글은 빌드 때 정해지니 빌드 때 세면 된다. 요청마다 셀 필요가 없다.
- **무엇을 셀까?** 코드 블록까지 세면 코드가 많은 글이 실제보다 훨씬 길게 나온다. 코드는 읽는다기보다 훑어보니 빼는 게 맞다.

본문에서 코드 블록만 빼고 글자를 세려면 마크다운을 직접 분석해야 할 것 같았는데, fumadocs가 이미 해 둔 게 있었다. **`structuredData`**다.

fumadocs-mdx는 빌드할 때 검색 기능용으로 본문에서 **제목, 문단, 표의 텍스트만** 뽑아 둔다. 코드 블록은 들어 있지 않다. 딱 원하던 데이터다.

```ts title="src/lib/posts.ts"
const CHARS_PER_MINUTE = 500;

function readingMinutes(contents: { content: string }[]) {
  const chars = contents.reduce((sum, { content }) => sum + content.replace(/\s/g, '').length, 0);
  return Math.max(1, Math.round(chars / CHARS_PER_MINUTE));
}

// getPosts() 안에서
readingMinutes: readingMinutes(page.data.structuredData.contents),
```

- 공백은 빼고 센다.
- 아주 짧은 글도 "0분"이 아니라 최소 "1분"으로 보이게 했다.

## 4. 확인: 임시 글로 테스트

글이 전부 2026년이라 연도 묶기가 제대로 되는지 볼 수가 없었다. 날짜가 2025년인 임시 글을 하나 만들어서 확인했다.

- 홈에 **2026**, **2025** 두 묶음이 생겼다.
- 가장 오래된 글의 "이전 글"이 임시 글로 나왔다.

확인이 끝나고 임시 글은 지웠다. 화면으로 보기 어려운 경우를 테스트할 때 쓸 만한 방법이다.

## 마무리

- 연도 묶기, 이전/다음 글은 **정렬된 배열 하나**로 해결된다. 정렬이 이미 되어 있으면 로직이 단순해진다.
- 최신순 배열에서 이전(오래된) 글은 `i + 1`, 다음(최신) 글은 `i - 1`이다.
- 읽는 시간은 빌드 때, 코드 블록을 뺀 글자로 센다. fumadocs의 `structuredData`가 그 텍스트를 이미 갖고 있다.
