## 1. 항성: 빛나는 공과 빛은 따로다

```tsx title="src/components/explore/Star.tsx"
<mesh ref={ref}>
  <icosahedronGeometry args={[0.9, 2]} />
  <meshBasicMaterial color="#ffd27a" />

  {/* 빛 번짐: 조금 더 큰 반투명 구를 자식으로 겹친다 */}
  <mesh>
    <sphereGeometry args={[1.5, 32, 32]} />
    <meshBasicMaterial color="#ffb347" transparent opacity={0.12} depthWrite={false} />
  </mesh>
</mesh>
```

- 항성은 **`MeshBasicMaterial`**이다. 빛 계산을 하지 않고 정해진 색을 그대로 칠하니, 조명과 상관없이 늘 밝게 보인다. 스스로 빛나는 물체처럼 보인다.
- 하지만 이 공이 주변을 비추지는 않는다. 실제로 행성을 비추는 건 **같은 자리에 둔 `pointLight`**다.

```tsx title="src/components/explore/GalaxyCanvas.tsx"
<pointLight position={[0, 0, 0]} intensity={2.2} decay={0} color="#fff0d0" />
```

`decay`는 거리에 따라 빛이 약해지는 정도다. 기본값(2)이면 멀리 있는 행성이 거의 까맣게 된다. 은하처럼 거리 차이가 큰 장면에서는 `0`으로 꺼서 모든 행성을 같은 밝기로 비추게 했다. 이제 행성은 항성 쪽 면만 밝고 바깥쪽은 어둡다.

<Callout title="depthWrite={false}">
  반투명한 빛 번짐 구도 기본으로는 "여기에 물체가 있다"는 깊이 정보를 남긴다. 그러면 그 뒤에 있는 별이 가려진다. `depthWrite={false}`로 깊이 정보를 남기지 않게 하면 뒤의 별이 비쳐 보인다.
</Callout>

## 2. 별 2,000개는 Mesh가 아니라 Points 하나

별 하나를 Mesh 하나로 만들면 2,000개의 물체가 생기고, 물체마다 그리기 명령이 따로 나간다. 점만 찍으면 되는 경우에는 **Points**를 쓴다. 좌표 2,000개를 Geometry 하나에 담아 **한 번에** 그린다.

```tsx title="src/components/explore/Starfield.tsx"
const positions = useMemo(() => {
  const random = seededRandom(42);
  const array = new Float32Array(COUNT * 3); // [x, y, z, x, y, z, ...]
  for (let i = 0; i < array.length; i++) array[i] = (random() - 0.5) * SPREAD;
  return array;
}, []);

return (
  <points>
    <bufferGeometry>
      <bufferAttribute attach="attributes-position" args={[positions, 3]} />
    </bufferGeometry>
    <pointsMaterial color="#ffffff" size={0.12} />
  </points>
);
```

- 좌표는 `[x, y, z, x, y, z, ...]`처럼 한 줄로 늘어놓은 `Float32Array`다. `args={[positions, 3]}`의 3은 "점 하나에 숫자 3개"라는 뜻이다.
- `attach="attributes-position"`은 `geometry.attributes.position = new BufferAttribute(...)`와 같다.

### 왜 Math.random()이 아니라 씨앗 난수일까

`Math.random()`을 쓰면 새로고침할 때마다, 그리고 서버와 브라우저에서 별 위치가 달라진다. **씨앗(seed)이 같으면 항상 같은 순서로 숫자가 나오는 난수 함수**(mulberry32)를 써서 매번 같은 하늘이 나오게 했다.

## 3. 행성에 고리와 위성 달기

### 고리: Torus

```tsx
<mesh rotation={[1.3, 0, 0]}>
  <torusGeometry args={[size * 1.7, 0.03, 8, 64]} />
  <meshBasicMaterial color={color} transparent opacity={0.6} />
</mesh>
```

`TorusGeometry`는 도넛 모양이다. `args`는 [도넛 반지름, 관 굵기, 관 둘레 분할, 도넛 둘레 분할]. 관을 아주 얇게 하면 토성 고리처럼 보인다. 반지름을 행성 크기의 1.7배로 잡아서 행성이 커지면 고리도 따라 커진다.

### 위성: Octahedron + emissive

```tsx
<mesh position={[size + 0.35, 0, 0]}>
  <octahedronGeometry args={[0.08]} />
  <meshStandardMaterial color="#ffffff" emissive={color} emissiveIntensity={0.6} flatShading />
</mesh>
```

팔면체는 꼭짓점 6개짜리 보석 모양이다. `emissive`는 빛을 받지 않아도 스스로 내는 색이라, 그늘진 쪽에서도 위성이 은은하게 보인다.

### 고리는 행성 본체의 자식으로 넣으면 안 된다

고리를 행성 본체 Mesh의 **자식**으로 넣으면, 행성이 자전할 때 기울어진 고리도 같이 돌면서 흔들린다. 자식은 부모의 회전을 그대로 물려받기 때문이다.

그래서 **자리는 빈 group이 잡고, 자전은 본체만** 하게 나눴다.

```
group (행성 자리)
 ├─ mesh: 행성 본체 (자전)
 ├─ mesh: 고리 (기울어진 채 고정)
 └─ 위성들
```

`group`은 모양이 없는 빈 상자다. 자식들을 한꺼번에 옮기거나 돌릴 때 쓴다. 이 성질이 다음 단계의 핵심이다.

## 4. 공전: 부모를 돌리면 자식이 원을 그린다

행성이 항성 주위를 돌게 하려면 매 프레임 `x = cos(t) × r`, `z = sin(t) × r`를 계산하면 된다. 하지만 **group 계층**을 쓰면 계산이 필요 없다.

```
group: 공전축 (원점 = 항성 자리, 매 프레임 y축으로 돈다)
 ├─ mesh: 궤도선
 └─ group: 행성 자리 (공전축에서 x로 distance만큼 떨어져 가만히 있다)
     ├─ 행성 본체, 고리
     └─ group: 위성 공전축 (돈다)
         └─ mesh: 위성
```

```tsx title="src/components/explore/Planet.tsx"
useFrame((_, delta) => {
  orbit.current.rotation.y += delta * orbitSpeed; // 공전
  body.current.rotation.y += delta * 0.4; // 자전
  moonOrbits.current.forEach((moonOrbit, k) => {
    moonOrbit.rotation.y += delta * moonSpeed * (1 - k * 0.05); // 위성 공전
  });
});
```

- 공전축은 항성 자리(원점)에서 제자리 회전만 한다.
- 그 안의 행성은 x로 6만큼 떨어진 자리에 **가만히** 있다. 그런데 부모가 돌면 자식은 부모 기준의 자리를 유지하니, 결과적으로 원을 그리며 돈다. 팽이 가장자리에 붙인 스티커가 팽이를 따라 도는 것과 같다.
- 위성도 같다. 행성 안에 위성 공전축을 두고 돌리면 위성은 행성 주위를 돌고, 행성이 공전하면 **같이 따라간다**.
- 궤도선(얇은 Torus)도 공전축 안에 있지만, 도넛은 돌아도 모양이 같아서 공전해도 티가 안 난다.

## 5. 만난 문제: 슬라이더를 움직이면 행성이 처음 자리로 순간 이동했다

처음에는 공전축 하나에 기울기와 회전을 다 맡겼다.

```tsx
<group ref={orbit} rotation={[tilt, 0, 0]}> {/* 기울기 */}
```

`useFrame`은 이 group의 `rotation.y`를 계속 늘린다. 그런데 Leva 슬라이더를 움직이자 행성이 궤도의 처음 자리로 **순간 이동**했다.

### 원인

슬라이더를 움직이면 React가 컴포넌트를 다시 그린다. 그때 `rotation={[tilt, 0, 0]}` prop이 다시 적용되면서 **y가 0으로 덮어써졌다.** React가 주는 값과 `useFrame`이 매 프레임 바꾸는 값이 같은 속성(`rotation`)에서 부딪힌 것이다.

### 해결

group을 둘로 나눴다. 바깥은 React가 주는 값(기울기, 시작 각도)만, 안쪽은 `useFrame`이 바꾸는 값(회전)만 맡는다.

```tsx
<group rotation={[tilt, startAngle, 0]}> {/* React prop: 고정 */}
  <group ref={orbit}> {/* useFrame: 계속 회전 */}
    ...
  </group>
</group>
```

위성도 같은 이유로 "시작 각도 group"과 "공전축 group"을 나눴다.

<Callout type="tip" title="prop과 useFrame은 겹치지 않게">
  React prop으로 주는 값과 `useFrame`에서 매 프레임 바꾸는 값은 서로 다른 속성, 또는 서로 다른 물체에 두는 게 안전하다. 겹치면 다시 그릴 때마다 prop 값으로 돌아간다.
</Callout>

## 마무리

- 스스로 빛나 보이는 물체는 `MeshBasicMaterial`, 실제로 비추는 빛은 같은 자리의 `pointLight`로 따로 만든다. 거리 차이가 큰 장면은 `decay={0}`.
- 점이 많을 때는 Mesh 여러 개 대신 **Points 하나**로 한 번에 그린다. 위치는 씨앗 난수로 항상 같게.
- 자식은 부모의 위치와 회전을 물려받는다. **공전축 group만 돌리면** sin, cos 없이 공전이 된다.
- React prop과 `useFrame`이 같은 속성을 건드리지 않게 group을 나눈다.
