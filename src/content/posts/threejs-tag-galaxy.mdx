[지난 글](/posts/threejs-solar-system)에서 행성 하나짜리 행성계를 만들었다. 이제 블로그의 **진짜 태그와 글**로 채운다.

- 태그 하나 = 행성 하나
- 그 태그의 글 하나 = 위성 하나
- 글을 새로 쓰면 빌드할 때 행성과 위성이 **자동으로** 늘어난다

완성하면 이렇게 된다. 지금 이 블로그의 태그와 글로 그려진 은하다.

## 1. 서버에서 데이터를 만들어 넘기기

3D 장면은 클라이언트 컴포넌트지만, 글 목록은 서버에서 읽는다. 페이지(서버 컴포넌트)에서 필요한 모양으로 만들어 props로 넘겼다.

```tsx title="src/app/explore/page.tsx"
export default function ExplorePage() {
  const posts = getPosts();
  const galaxy: GalaxyTag[] = getTags().map(({ tag }) => ({
    tag,
    posts: posts.filter((post) => post.tags.includes(tag)).map(({ title, url }) => ({ title, url })),
  }));

  return <GalaxyCanvas galaxy={galaxy} />;
}
```

```ts title="src/components/explore/types.ts"
export type GalaxyTag = {
  tag: string;
  posts: { title: string; url: string }[];
};
```

- 서버에서 클라이언트로 넘기는 props는 JSON처럼 직렬화할 수 있는 값이어야 한다. 그래서 필요한 것(제목, 주소)만 골라 넘겼다.
- `getTags()`는 글이 많은 태그부터 정렬되어 있다. 그 순서가 그대로 **안쪽 궤도부터** 행성 순서가 된다.

## 2. 위치, 크기, 색을 손으로 정하지 않기

태그가 몇 개일지 모르니 행성마다 값을 적을 수 없다. **몇 번째 태그인지(index)**와 **글 수**로 계산했다.

```tsx title="src/components/explore/Planet.tsx"
const postCount = data.posts.length;
const distance = firstOrbit + index * spacing; // 안쪽부터 차례로 바깥 궤도
const size = Math.min(0.35 + postCount * 0.12, 1.2); // 글이 많을수록 크게, 최대 1.2
const color = PALETTE[index % PALETTE.length]; // 색 목록에서 순서대로
const hasRing = postCount >= 3; // 3편 이상이면 고리
const orbitSpeed = 0.15 / (1 + index * 0.25); // 바깥 궤도일수록 느리게
const startAngle = (index / total) * Math.PI * 2; // 둘레에 고르게 흩어 놓기
const tilt = Math.sin(index * 7.3) * 0.15; // 궤도마다 조금씩 다른 기울기
```

- `startAngle`이 없으면 모든 행성이 처음에 한 줄로 서 있다. 한 바퀴(2π)를 태그 수로 나눠 출발 자리를 흩었다.
- 기울기는 난수 대신 `sin(index × 7.3)`을 썼다. 들쭉날쭉해 보이면서도 **항상 같은 값**이 나온다.
- 이렇게 해 두면 태그가 4개든 40개든 같은 코드로 그려진다. 태그가 너무 많아지면 `spacing` 같은 숫자 몇 개만 고치면 된다.

  지난 글까지는 행성 하나의 값을 슬라이더로 조절했다. 행성이 여러 개가 되니 행성마다 패널을 만들 수 없어서, 은하 전체에 같이 쓰는 값(첫 궤도, 궤도 간격, 공전 속도 등)만 남겼다.

## 3. 이름표 붙이기

### 처음 방법: drei의 Html

drei에는 3D 좌표에 HTML을 붙이는 `<Html>`이 있다. 행성 아래에 붙이면 행성을 따라다니고, 글자는 항상 화면을 바라본다.

```tsx
<Html position={[0, -(size + 0.45), 0]} center>
  <span>#{data.tag}</span>
</Html>
```

화면에는 잘 나왔는데, 콘솔에 에러가 **9개** 떴다. 행성 수와 같았다.

```
Attempted to synchronously unmount a root while React was already rendering.
```

### 원인

`<Html>`은 이름표 하나마다 **작은 React 앱(root)을 따로** 만든다. React 19 개발 모드는 컴포넌트를 한 번 지웠다가 다시 그리면서 문제가 없는지 검사하는데(Strict Mode), 그때 이 작은 앱들을 그리는 도중에 지우려다 에러가 났다. 이름표마다 하나씩이라 9개였다.

### 해결: 이름표 층을 하나만 두고 위치를 직접 계산

Canvas 위에 **HTML 이름표 층을 하나** 겹쳐 두고, 매 프레임 각 행성의 화면 좌표를 계산해서 옮기기로 했다.

1. 행성 아래에 모양 없는 빈 group(기준점)을 둔다. 행성과 같이 움직인다.
2. 매 프레임 기준점의 **실제 좌표**를 구한다. 부모들의 공전과 기울기가 다 반영된 좌표다.
3. 그 좌표를 **카메라로 찍었을 때 화면의 어디인지**로 바꾼다.
4. px로 환산해서 이름표의 `transform`을 바꾼다.

```tsx title="src/components/explore/PlanetLabels.tsx"
const point = new Vector3();

export function PlanetLabelsUpdater({ anchors, labels }) {
  useFrame(({ camera, size }) => {
    for (const [tag, anchor] of anchors.current) {
      const el = labels.current.get(tag);
      if (!el) continue;

      anchor.getWorldPosition(point); // 2. 실제 좌표
      point.project(camera); // 3. 화면 좌표: x, y가 -1 ~ 1

      const x = ((point.x + 1) / 2) * size.width;
      const y = ((1 - point.y) / 2) * size.height; // 화면은 위가 0이라 y를 뒤집는다
      el.style.transform = `translate(-50%, 0) translate(${x}px, ${y}px)`; // 4.
      el.style.opacity = point.z > 1 ? '0' : '1'; // 카메라 뒤쪽이면 숨긴다
    }
  });
  return null;
}
```

- `project(camera)`가 핵심이다. 3D 좌표를 화면 좌표(-1~1)로 바꿔 준다. -1이 왼쪽(아래), 1이 오른쪽(위)이다.
- 1초에 60번 바뀌는 값이라 React state가 아니라 **DOM의 style을 직접** 바꾼다. state로 하면 매 프레임 다시 그리기가 일어난다.
- `point`를 컴포넌트 밖에서 한 번만 만든 것도 같은 이유다. 매 프레임 `new Vector3()`를 만들면 버려지는 객체가 계속 쌓인다.
- 이름표 층에는 `pointer-events-none`을 줘서 마우스가 그 아래 Canvas로 그대로 간다. 드래그가 막히지 않는다.

기준점과 이름표는 태그 이름을 키로 한 `Map` 두 개로 짝지었다. 각자 ref 콜백에서 자기를 등록한다.

```tsx
<group
  position={[0, -(size + 0.45), 0]}
  ref={(el) => {
    if (el) anchors.current.set(data.tag, el);
    else anchors.current.delete(data.tag); // 사라지면 지운다
  }}
/>
```

에러는 없어졌고, 다음 단계에서 "? 미탐험"처럼 이름표 내용을 바꾸기도 쉬워졌다. 이름표가 그냥 React가 그리는 `<span>`이기 때문이다.

## 마무리

- 3D 장면이 클라이언트여도 데이터는 서버 페이지에서 만들어 props로 넘긴다. 필요한 값만 골라서.
- 개수를 모르는 물체는 **index와 데이터로 계산**해서 배치한다. 같은 결과가 필요하면 난수 대신 `sin` 같은 식을 쓴다.
- drei `<Html>`은 편하지만 이름표마다 React root를 만든다. 개수가 많으면 이름표 층 하나에 `project(camera)`로 직접 위치를 계산하는 방법이 가볍다.
- 매 프레임 바뀌는 값은 state가 아니라 DOM이나 three.js 객체를 직접 바꾼다.
